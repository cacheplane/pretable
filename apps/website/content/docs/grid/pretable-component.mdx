`<Pretable>` is the simplest way to render a grid. Three props, sensible defaults, working in one import.

```tsx
import { Pretable, type PretableColumn } from "@pretable/react";

interface Person extends Record<string, unknown> {
  id: string;
  name: string;
  role: string;
  city: string;
}

const columns: PretableColumn<Person>[] = [
  { id: "name", header: "Name", value: (r) => r.name },
  { id: "role", header: "Role", value: (r) => r.role },
  { id: "city", header: "City", value: (r) => r.city },
];

const rows: Person[] = [
  { id: "1", name: "Ada", role: "Engineer", city: "London" },
  { id: "2", name: "Grace", role: "Admiral", city: "New York" },
  { id: "3", name: "Linus", role: "Maintainer", city: "Helsinki" },
];

export function People() {
  return <Pretable rows={rows} columns={columns} />;
}
```

## Props

Two are required. The rest are forwarded verbatim to the underlying [`<PretableSurface>`](/docs/grid/pretable-surface#props) — same types, same behavior — so reach for that page for the detail.

| Prop                   | Type                                                        | Required | Description                                                                                              |
| ---------------------- | ----------------------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------- |
| `columns`              | `PretableColumn<TRow>[]`                                    | yes      | Column definitions. See [API reference](/docs/grid/api-reference#pretablecolumntrow) for the full shape. |
| `rows`                 | `TRow[]`                                                    | yes      | Row data. Generic over your row type (defaults to `Record<string, unknown>`).                            |
| `getRowId`             | `(row: TRow, index: number) => string`                      | no       | Custom row key. Defaults to `row.id` if it's a string or number; otherwise the row's index.              |
| `rowSelectionColumn`   | `RowSelectionColumnConfig`                                  | no       | Turn on the three-state checkbox column. See [Selection](/docs/grid/selection).                          |
| `onRowSelectionChange` | `(rowIds: string[]) => void`                                | no       | Fired with the full list of selected row ids.                                                            |
| `onRowActivate`        | `(input: PretableRowActivateInput<TRow>) => void`           | no       | Fired on Enter or double-click over a row.                                                               |
| `onCellEdit`           | `(payload) => void \| Promise<void>`                        | no       | Commit handler for cell editing. Editing is inert without it. See [Editing](/docs/grid/editing).         |
| `onCopy`               | `(args) => CopyPayload \| null`                             | no       | Replace the default TSV serializer. See [Clipboard](/docs/grid/clipboard).                               |
| `copyToClipboard`      | `(payload: CopyPayload) => void \| Promise<void>`           | no       | Replace the clipboard write itself.                                                                      |
| `copyWithHeaders`      | `boolean`                                                   | no       | Prefix copied output with a header row. Defaults to `false`.                                             |
| `tabBehavior`          | `"wrap-rows" \| "exit"`                                     | no       | Tab key behavior. See [Keyboard](/docs/grid/keyboard).                                                   |
| `messages`             | `PretableSurfaceMessages`                                   | no       | Override the `aria-live` announcement strings.                                                           |
| `onColumnWidthsChange` | `(next: Record<string, number>) => void`                    | no       | Fired on resize drag-end with the full widths map.                                                       |
| `onColumnOrderChange`  | `(next: readonly string[]) => void`                         | no       | Fired on reorder drag-end with the new column id order.                                                  |
| `onColumnPinnedChange` | `(next: Record<string, "left" \| "right" \| null>) => void` | no       | Fired when pin state changes, with the full pinned map.                                                  |

There is no `viewportHeight`, no `state`, no telemetry, and no render overrides — that is the whole difference from `<PretableSurface>`.

## Defaults

`<Pretable>` wraps the engine with these hardcoded defaults:

- **Viewport height:** 320px (the scrollable container)
- **Cell rendering:** label-above-value layout (column header in a small dim line, value in the body)
- **Header rendering:** column header label + sort-direction indicator (`Newest` / `Oldest` / `Sort`)
- **No filter UI, and no controlled state** — the surface underneath still wires header click-to-sort, keyboard navigation, cell-range selection and clipboard, so those work. What `<Pretable>` gives you no way to reach is filtering, the grid handle, telemetry, and the controlled `state` slices.

If any of these defaults don't fit your use case, switch to [Custom rendering](/docs/grid/custom-rendering).

## Theming

`<Pretable>` emits the standard `[data-pretable-*]` data attributes, so `@pretable/ui/grid.css` styles the output. Drop in a theme + grid.css to skin it:

```css
@import "@pretable/ui/themes/excel.css";
@import "@pretable/ui/grid.css";
```

The grid renders with Excel's surface tones, gridlines, accent. Toggle `data-density` on `<html>` to switch density tiers (compact / standard / spacious); the engine watches that attribute and re-renders with the new heights. See [Theming Overview](/docs/theming) for the full theming model.

## Limitations

`<Pretable>` is intentionally thin. What it does not give you a way to reach:

- **A viewport height of your own** — it is hardcoded to 320px.
- **Filtering** — no filter UI, and no way to get at `grid.setColumnFilter` / `grid.replaceFilters`.
- **The grid handle** — no `onGridReady`, so nothing imperative: no programmatic sort, focus, transactions, or grouping.
- **Controlled state** — no `state` prop, so you cannot own the sort, filter, selection, or focus slices from the outside.
- **Telemetry** — no `onTelemetryChange`.
- **Custom cell or header components** — the label-above-value layout is fixed.
- **Row grouping** — no group panel, no `groupColumn`, no `onRowGroupsChange`.
- **Per-row measured heights** — `measuredHeights` is a `usePretable` option only.

Everything except the last is available on [`<PretableSurface>`](/docs/grid/pretable-surface), which is the same engine with every prop exposed. Drop all the way to [`usePretable`](/docs/grid/custom-rendering) only when you also want to own the rendering.

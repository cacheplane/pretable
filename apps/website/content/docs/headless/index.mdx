`@pretable/core` separates two framework-independent stores — `createLocalRowModel` owns rows, filters, sorting, grouping, aggregation, and expansion; `createGrid` adds optional UI state such as focus, selection, editing, viewport, and visual column layout. Neither renders DOM or requires React. Below is a complete renderer built on nothing but those two stores and `<table>`:

Sorting the columns, filtering by team, and selecting a row are all driven by `rowModel` and `grid` directly — there is no `<PretableSurface>` anywhere in this file. [First headless grid](/docs/headless/getting-started) walks through how it's built.

<Callout type="tip">
  A renderer reads only the rows it needs with `snapshot.range(start, end)`. The
  indexed model does not materialize the complete logical row set.
</Callout>

## When to reach for it

Use `@pretable/core` directly for a canvas renderer, another framework, or custom markup. If you only need a React grid, pass `rows` and `columns` to [`<PretableSurface>`](/docs/grid/pretable-surface); it creates and maintains the local row model for you.

## Install

```bash title="Terminal"
npm i @pretable/core
```
